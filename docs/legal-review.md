# 法律合规审查——开源发布前评估（2026-11-13）

> 性质声明：本文档是开发者的合规自查记录，**不构成法律意见**；重大商业决策前应咨询执业律师。
> 依据均来自公开检索（日期 2026-11-13），来源随条目标注。

## 一、开源许可证效力（结论：合规，注意两点）

**权威依据**：罗盒（VirtualApp）诉玩友案，广州知识产权法院（2021）粤 73 知民初 277 号，
判赔 50 万元，入选 2021 中国法院十大知识产权案件（来源：广州知识产权法院官网 gipc.gov.cn、开放原子开源基金会）。

裁判规则：
1. 中国法院**承认开源许可证的合同效力**（附解除条件的著作权许可合同）——「中国法院不管开源」是误区；
2. 违反许可证条款 → 授权自动终止 → 构成**著作权侵权**（违约/侵权竞合，权利人可择一主张）；
3. 已适用开源协议的版本**不能撤回许可**；权利人**不得**在开源协议之上附加商业使用限制条款。

**对 PowerFocus 的含义（自查）**：
- ✅ 项目采用 Apache-2.0（宽松协议），未使用 GPL 代码，无传染性问题（PyInstaller bootloader 例外已在 THIRD_PARTY_NOTICES 声明）；
- ✅ 义务清单：分发时保留 LICENSE 与 NOTICE、第三方许可声明——THIRD_PARTY_NOTICES.md 已建立，发布流程需将两文件随源码分发（源码仓库天然满足）；
- ⚠️ **红线**：不得在 Apache-2.0 之上附加「禁止商用」等额外限制条款（判例明确此类附加条款无效且矛盾）——当前仓库无此类条款，未来贡献守则也不得引入；
- ⚠️ 若未来引入 GPL 组件（如某些引擎适配），整个衍生作品将受 GPL 传染——引入任何新依赖前必须核其许可证（CONTRIBUTING 已有此要求）。

## 二、系统工具的法律边界（结论：合规，守住两条线）

**相关法条**：《刑法》第 285 条（非法侵入/控制计算机信息系统）、第 286 条（破坏计算机信息系统罪）
及两高《关于办理危害计算机信息系统安全刑事案件应用法律若干问题的解释》（法释〔2011〕19 号）。

**分析**：
- 第 286 条要求「违反国家规定」+ 对系统功能的破坏达到「后果严重」（司法解释门槛：
  造成 10 台以上系统不能运行 / 违法所得 5000 元以上等）。本应用**只在用户本人授权的本机**上
  调整进程优先级、电源方案、清理内存——属于用户对自己计算机的正常管理权限，不涉及
  「违反国家规定」的侵入或破坏行为；
- 第 285 条的防线在于**不构成对他人计算机的未授权控制工具**。本应用的安全模型天然满足：
  服务仅监听 127.0.0.1 回环、接口需本机令牌、无远程控制能力——这是合规优势，发布时应在
  README 显式声明（已声明「仅回环监听 · 令牌鉴权」）；
- ⚠️ **红线**：任何将应用改造为远程控制/未授权访问工具的行为超出本项目授权范围；
  贡献守则（CONTRIBUTING）已明确不接受「绕过安全机制」方向的贡献。

## 三、生成式 AI 合规（结论：当前形态不适用《暂行办法》，有一条红线）

**权威依据**：《生成式人工智能服务管理暂行办法》（2023，网信办等七部门）第二条适用范围
与官方答记者问（cac.gov.cn）：办法适用于「**向中华人民共和国境内公众提供**生成式人工智能服务」；
「未向境内公众提供生成式人工智能服务的研发、应用活动，**不适用**本办法」。

**对 PowerFocus 的含义（自查）**：
- ✅ 本项目以**开源软件**形式发布：模型由用户自选（本地 Ollama 或用户自填 API Key 的云端服务），
  开发者不运营任何面向公众的在线 AI 服务，**不构成「生成式人工智能服务提供者」**，
  不触发备案/登记义务；
- ✅ 本地快照数据（进程列表等）仅存本机（%LOCALAPPDATA%），不上传；
- ⚠️ **如实告知义务（个人信息保护层面）**：用户使用云端对话时，其输入内容由**用户自己配置的
  第三方模型服务商**处理——README/文档必须如实说明这一数据流向，不得暗示「零上传」；
- 🚫 **红线**：若未来将本项目变为托管服务/SaaS 向公众提供 AI 能力，将触发备案或登记路径
  （2026 年起「清朗」专项行动已将「应备未备」列为整治对象，见竞天公诚 2026 实务综述）——
  在走到那一步之前需要单独做合规评估。
