## 1. 结论先行

本周（第一步，走一）只做有证据、可回滚、可验收的子集：五项技术动作——复核回滚前置（首轮快照/锚点/演练已闭环，开工前补增量）；修电源计划守卫与降级；补规则动作存活复查；细分空 action 与令牌三态回执；做版本目录归档与备份二进制暂存。另放行四项前端/文案动作：kill 绑定回归验证、报错人话映射、忙碌态、旧数据过期标识。其余一律不进本周：热感知调度不立项，总线不重构，模块不去重，版本号体系不重写，不增新场景新规则。

不做的理由有三条：温度口径未校准、痛点无受害记录（产品 RICE 0.15 全场最低，监察否决 1）；五条生产通路零测试覆盖，无测试基础上动结构风险不可控；59 行未提交改动业务意图未评审，回滚基线必须先立稳再谈改代码。

需董事长拍板事项见第 10 章；核心是本周范围按"走一看二"收敛，而不是按"五类短板全修 + 热感知 + 扩展"一周压上。

### 2.6 双令牌对照（两套独立密钥，禁止混为一谈）

> 依据：底账 §2.2 L173 / L177-178；专档 11；`security.py:441-446`；`server.py:874`；`app.js:137`；`index.html:7`。HTTP 层鉴权与内核令牌是两条独立链路，生成方、存放位置、校验方、失效症状均不同。

| 对照项 | HTTP 层鉴权令牌（X-PF-Token / http.token） | 内核授权令牌（.auth_token） |

| 用途 | 校验浏览器/脚本对 `127.0.0.1:18080` 各 HTTP 接口的访问 | 校验写入命令总线的命令 JSON 是否来自合法服务端 |
| 生成方 | 服务端生成，落 `%LOCALAPPDATA%\PowerFocus\http.token`（32 B，2026-11-14 10:23:45） | 内核仅在令牌文件缺失时 `NewGuid().ToString("N")` 写入 `versions\v0.13\.auth_token`（34 B，2026-11-15 06:29:06）；重启不重生成 |
| 传递/注入 | 页面加载时 `server.py:874` 把令牌注入 `index.html:7` 的 `<meta name="pf-token">`；前端 `app.js:137` 所有请求带头 `X-PF-Token`；**不是** `Authorization: Bearer` | `bus_call`（`server.py:735-736`）给每条命令 JSON 注入 `token` 字段；客户端无法覆盖，服务端先剥除自带 token（`server.py:967`） |
| 校验方 | `security.py:441` 取 `headers.get("x-pf-token", "")`，L442-446 不匹配即 401；`/api/health` 为豁免端点，无令牌也 200 | 内核闸门 L2255-2257：`Get-AuthToken` 每次实时读 `.auth_token` 并 Trim，与命令件 `token` 字符串比对，不匹配回 `ERROR: 命令总线认证失败` |
| 失效症状 | 误用 `Authorization: Bearer` 调业务接口 → 401 Unauthorized；health 仍 200，表现为"只放行浏览器、拒绝脚本"（专档 11，已闭环） | 命令件缺 token 字段 / 空串 / 不匹配 → 命令不执行，回执认证失败（专档 01） |
| 边界 | 令牌不进命令总线；HTTP 响应不回显内核令牌 | 令牌不出服务端；前端、引擎进程、回执日志不得持有或回显（沈工红线 2） |

## 6. 两者之间的接口：六个预留字段

> 兼容规则（沈工 §⑤）：命令 JSON 加可选键，旧内核只取具名属性、未知键忽略；结果侧并行写可选侧车 `{id}.result.json`；`bus_receipt.gc_done` 已同时遍历 `*.result.txt` 与 `*.json`，侧车天然纳入 GC。第一步服务端解析路径一行不改。

| 字段 | 类型/缺省 | 第一步怎么写 | 第二步何时启用 | 启用条件 |
|---|---|---|---|---|
| `request_id` | string，缺省复用现有 `idempotency_id`，不新增生成器 | 服务端写入；内核忽略 | 内核/回执回带同一 ID，服务端按 ID 关联回执、判定孤儿归属 | 内核实例冻结；兼容矩阵确认；服务端侧车解析就位 |
| `deadline_ms` | int \| null，null 沿用现有 30s 超时 | 仅服务端自用；内核忽略 | 内核据此判定"超时未执行"并回三态回执 | 命令级超时契约在内核落地；三态回执双解析并存方案确认 |
| `priority` | enum `normal`/`high`，缺省 `normal` | 写入但不参与排序 | 调度器按优先级排队/插队 | 背压与队列深度信号就位；多命令并发排队有实测证据 |
| `engine_target` | string，缺省 `auto` | 写入但不路由 | 多引擎实例就绪后按值分发 | 第二步需求证实（红线 3：瓶颈未证实不引抽象层）；实例隔离标识就位 |
| `error_code` | string \| null，缺省 null | 结果侧车预留，第一步不写不读 | 内核产出机器可读失败分类，前端按码展示 | 前端 D-02 映射表与 error_code 对应关系先定义并签字确认（沈工 §⑧-1） |
| `elapsed_ms` | int \| null，缺省 null | 结果侧车预留 null | 内核记录执行耗时，供失败分类与性能观测 | 侧车文件 GC 口径确认；观测字段口径评审通过 |

**"第一步只写不读"的风险**：命令文件略增几个键；侧车文件在旧内核下不存在（无副作用）；主要风险是**误用**——开发误以为第二步已启用，去消费尚未产生的字段。对策：字段名在第一步文档中标注 `reserved`；代码注释注明"第二步启用前不读"；评审检查项加一条"不得消费 reserved 字段"。

## 8. 长期迭代机制（董事长钦定四问）

### 8.1 每一轮闭环的标准动作与产物

1. **问题单**：按档案库 README 固定九项落盘（症状/证据/根因/修法/验证命令/回滚方法/复发检索关键词/状态/阻塞原因），证据必须到日志文件:行号、代码文件:行号或实测值；未坐实推断标"待证实"。
2. **复现**：先跑深度测试七条——① PowerShell 语法扫描（Parser 扫当前内核与 lib 全部 .ps1，不执行）；② Python pytest + py_compile 改动文件；③ 服务探活 `/api/health`；④ 内核心跳 tick 增长、`cmd_bus=true`；⑤ 端口占用与单实例（18080 有监听，不重复拉起）；⑥ 近 30 分钟 ERROR/WARN 扫描；⑦ **资源一致性**（判定运行包是不是最新，三条任一不满足即判旧包）：exe mtime 与监听 18080 进程的 StartTime 比对，进程启动须晚于 exe 生成；`/static/{app.js,style.css,index.html}` 返回长度与本地源码比对；关键词匹配（如新规则类名、`killBtn`、`skel` 清理标记）。**任一项失败即停手，不得带故障进入下一轮**；探针异常先排障，不在故障基线上叠加变更。
3. **修复**：按 WBS 拆任务，每项有责任人、截止时间、验收标准；改前快照/备份。
4. **验证**：可复跑命令或测试留证据行；P0 现场命令（QA V1–V8）通过；禁止只写"已修复"。否决 4 持续有效：`test-mem-guard.ps1` 路径常量修复前，验收结论不得写"MemGuard 守护验证通过"。
5. **归档**：问题一律归档到 `E:\电脑错误收集中心\应用问题\正常软件\PowerFocus问题库\`，编号续排——本轮目录实测专档最大编号 **11**（01–11；另存两份 07 双档待下一轮合并去重），下一轮新档从 **12** 起编；归档前以目录实际文件为准再核一次最大编号。专档状态改"已闭环"必须有真机或测试跑通证据；挂账项写清阻塞原因。
6. **看板更新**：回填 `00-迭代看板.md` 状态、证据、闭环计数；累计闭环口径见看板 §六（挂账/观察中不计）。

### 8.3 无人值守怎么跑

- **不引入自动改代码的无人值守**。第一步与第二步的代码动作都必须人审、人执行、人验收。
