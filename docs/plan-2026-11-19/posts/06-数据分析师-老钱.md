## ③ 温度专项结论

### 3.1 三条通道同时刻实测（21:51:11）

| 通道 | 读数 | 命令 |
|---|---|---|
| ACPI 热区 ECTZ_0 / TZ01_0 | 73.1℃ / 72.1℃ | `Get-CimInstance -Namespace root\WMI -ClassName MSAcpi_ThermalZoneTemperature` |
| GPU（RTX 5060 Laptop） | 54℃，利用率 8%，显存 2467/8151 MiB，功耗 16.17 W | `nvidia-smi --query-gpu=temperature.gpu,utilization.gpu,memory.used,memory.total,power.draw` |
| CPU 占用 | 6.4%（4 次采样 4.4 / 7.2 / 6.5 / 6.4，均值 6.1%） | `Get-Counter '\Processor(_Total)\% Processor Time'` |
| LHM 内核 Tctl/Tdie（21:50:44 落盘记录） | Tctl 85.4℃，CCDmax 79.9℃，GPU 53.9℃，source=lhm | `temp-20261119.jsonl` 末条 |

**关键事实**：同一低负载时刻，LHM 内核通道 85.4℃ 与 ACPI 热区 73.1℃ 相差 12.3℃。两条通道在空闲下就存在稳定差值，证明它们**不是同一个物理量**：ACPI 热区是主板/机箱级平台传感器，粗粒度、滞后；LHM 经内核驱动直读 CPU 封装内 DTS（Tctl/Tdie）。

### 3.3 对 94–95℃ 来源的三种解释（各附支持/反对证据）

**解释一：采样点不同（内核 DTS/Tctl vs ACPI 平台热区）。**
- 支持：历史四天 LHM Tctl 反复进入 94–95℃；同时刻空闲对照两通道差 12.3℃；ACPI 通道对内核瞬态不敏感（今日 21:32 Tctl 95.2 → 21:50 85.4 期间，ACPI 一直 73.1/72.1 几乎不动）。
- 反对：12℃ 通道差在空闲下即存在，不能把负载温差全部归于采样点；本机无第二个内核级传感器（HWiNFO/BIOS）做交叉校准。

**解释二：负载时点不同（94–95 出现在推理/训练突发负载，73 出现在空闲采样）。**
- 支持：≥90℃ 记录与负载时段同步；基线采样 CPU 仅 6.1%。
- 反对：若纯负载差，ACPI 应跟随上升，实测未跟随；时点差异只能解释部分差值，不能解释通道口径差。

**解释三：读数口径/软件换算差异（Tctl≠结温、LHM 偏移未校准、兜底源混用）。**
- 支持：11-16 CCDs Max 出现 100.4℃ 异常尖峰；11-15 有 298 条 nvidia-smi 兜底记录（cpu 字段为空）；AMD Tctl 含散热策略偏移，不等于 Tjunction；空闲 6.1% 负载下 Tctl 仍有 85.4℃，存在读数偏移嫌疑。
- 反对：94–95℃ 区间在四个工作日重复出现且与 GPU 升温同步，不像单点换算错误；jsonl 字段结构完整、source 标注清楚。

### 3.4 最终裁定

1. **"94–95℃"采纳为 LHM 通道 CPU Tctl/Tdie 在负载时段的历史观测值（A 级，落盘可复现）**；"73.1/72.1℃"为 ACPI 热区空闲实测值（A 级）。两者禁止互相替代、禁止取平均、禁止并列做阈值对比。
2. 热感知调度必须先固定通道：CPU 热保护用 LHM Tctl/Tdie；ACPI 热区仅作平台级参考；GPU 用 `nvidia-smi temperature.gpu`。
3. LHM 绝对值未经第二传感器校准（校准状态 C 级），在完成校准前，调度阈值须留 10℃ 以上余量；空闲 85.4℃ 的成因（环境温度/散热/驱动偏移）未验证，不得直接判"过热"。

### 7.3 MemGuard `raised=1` 语义

**复核问题**：raised 字段是"已提升优先级"还是别的计数？
