测试环境与方法

  • 模型服务：llama-server（PID 38352，127.0.0.1:8080），参数 -ngl 20 -t 16 -c 8192 --cache-type-k q8_0 --cache-type-v f16（部署最优参数）
  • 竞争负载：24 个 node 进程（crypto sha256 死循环）占 ~26.8 核，整机 93–94%
  • 测量：每阶段 3 次生成取中位数；生成期间用进程 CPU 累计差值法实测 llama 占核数
  • 触发：虚拟桌面（桌面2）+ 工具自身代码路径等效触发（与托盘"开始聚焦"同一函数）
  • 原始数据：E:\PowerFocus\bench-results.jsonl

诚实说明与局限

  • 托盘点击流：盾牌图标位于托盘溢出区，自动化通道 7 次尝试均误触输入法/音量/网络面板（坐标随任务栏重排漂移）；聚焦动作改为 dot-source 主程序调用同源函数完成。托盘图标真人点击验证建议首次按《使用说明》手动走一遍。
  • 温和 vs 激进：本场景吞吐几乎持平（波动范围内）；激进档的价值是"保底抢占保证"而非更高吞吐。
  • 电源计划：测试全程本机已处于高性能计划（部署期设置），故本测试中该维度无差异。
  • 解除聚焦：恢复电源计划与降级进程；目标优先级保持 High（工具设计行为）。
  • 测试后已清理：恢复 177 个进程为 Normal、停止 27 个竞争进程；llama-server 与托盘工具保持运行。
