# 电脑算力调度中心 · 调动 vs 不调动 实测对比报告

- 测试日期：2026-11-02
- 测试对象：Qwen3.8-27B-UD-Q4_K_M（15.33GB）@ llama.cpp b12032（CUDA 13）+ 电脑算力调度中心（E:\PowerFocus\电脑算力调度中心.ps1）
- 测试方式：虚拟桌面（桌面2）+ 算力竞争环境下，三阶段对比实测（不调动 / 温和聚焦 / 激进聚焦），每阶段 3 次生成取中位数

---

## 一、核心结论（先行）

| 阶段 | 中位生成速度 | 相对基线 | llama CPU 占比 | llama 优先级 | 被降级进程数 | 整机负载 |
|---|---|---|---|---|---|---|
| 基线（不调动） | **1.20 t/s** | — | 34.4% | Normal | 12 | 94% |
| 温和聚焦 | **1.32 t/s** | **+10.0%** | 35.3% | **High** | 17 | 93% |
| 激进聚焦 | **1.31 t/s** | **+9.2%** | 35.9% | **High** | **177** | 93% |

**一句话结论**：在 27 核被竞争进程占满（整机 94%）的环境下，调用算力调度中心（无论温和/激进）都能让 Qwen3.8-27B 的生成速度提升约 **10%**（1.20 → 1.31~1.32 t/s）；温和档已拿到绝大部分收益，激进档的额外价值是把 165+ 个竞争进程全部降级，保证目标进程在任意负载下都能优先抢占 CPU（本场景吞吐与温和档持平，属波动范围内）。

## 二、测试环境与条件

- 硬件：AMD Ryzen 9 8940HX（16C/32T）+ RTX 5060 Laptop 8GB + 32GB 内存
- 模型服务：llama-server（PID 38352，端口 127.0.0.1:8080），参数 `-ngl 20 -fa off -c 8192 --cache-type-k q8_0 --cache-type-v f16 -t 16 -tb 8 --temp 0.7 --top-k 20 --top-p 0.8 --presence-penalty 1.5 --min-p 0`（与部署最优参数一致）
- 竞争负载：24 个 node 进程（crypto sha256 死循环）占满 ~26.8 核，整机负载 93–94%
- 测量脚本：`bench-phase.ps1`（每阶段 3 次生成，取 tokens/s 中位数；生成期间用进程 CPU 累计差值法实测 llama-server 占用核数/全机占比）；`sample-gen.ps1`（单次生成+CPU 采样，用于基线补充采样）
- 触发方式：虚拟桌面 GUI 操作 + 工具自身代码路径等效触发（详见"六、诚实说明"）

## 五、各维度解读

1. **生成速度（核心指标）**：聚焦后稳定 +9~10%。竞争环境下 CPU 时间片是稀缺资源，High 优先级让 llama-server 在调度器中排在前列，直接转化为吞吐提升。
2. **CPU 份额**：34.4% → 35.3% → 35.9%。聚焦后 llama 抢到的核数略增（11 → 11.3 → 11.5），与 tps 提升方向一致。
3. **激进档降级效果**：177 个非白名单进程被降为 BelowNormal（含全部 27 个竞争 node 进程）；基线时全机仅 12 个 BelowNormal 进程。白名单保护了系统关键进程（csrss/dwm/explorer 等）不受影响。
4. **温和 vs 激进**：本测试吞吐几乎持平（1.32 vs 1.31）。原因：llama-server 已是 High，在饱和负载下 gains 主要来自优先级；激进档的降级是"保底/抢占保证"——保证即使负载更高、或目标需要突发算力时，竞争者也抢不过它。
5. **电源计划**：本机在测试全程已处于"高性能"电源计划（部署期设置后一直保持），因此本测试中电源计划维度无差异；在默认"平衡"计划下使用工具时，工具会把计划切到高性能并在解除聚焦时恢复原计划。

## 六、诚实说明与局限

1. **托盘菜单点击流**：已创建虚拟桌面（桌面2）并尝试用自动化通道右键盾牌托盘图标，但图标位于系统托盘溢出区，连续 7 次尝试均误触输入法/音量/网络面板（图标坐标随任务栏重排漂移）。本次聚焦动作改为 dot-source 主程序、调用工具自身函数（Start-GentleFocus / Start-AggressiveFocus / Stop-Focus）等效触发——与托盘"开始聚焦"执行的是同一份代码。托盘图标的真人点击验证仍建议首次使用按《使用说明》手动走一遍（选择目标进程 → 开始聚焦）。
2. **方差**：激进档 run1=1.41 波动较大（该次 tokens=183，生成内容较短），中位数口径下与温和档持平。结论基于中位数，样本 3 次/阶段。
3. **解除聚焦的行为**：解除聚焦会恢复电源计划并恢复被降级进程为 Normal，但**目标进程优先级保持 High**（工具设计如此，聚焦期间一直保证最高优先级）；如需完全复原需手动调整或重启目标进程。
4. **环境清理**：测试结束后已恢复全部 177 个被降级进程为 Normal、停止 27 个竞争进程；llama-server（PID 38352）与托盘工具保持运行（符合"长期监管"需求）。
5. **基线 CPU 占比**：早期脚本采样窗口落在生成间隙（llama 空闲），读数 0% 已废弃；报告采用的 34.4% 为生成期间实测值（补充采样）。

## 七、建议

- 日常使用：**温和档**即可获得 ~10% 收益，对系统其他进程影响最小。
- 需要绝对保证（如负载极高、同时开多个吃 CPU 的程序）：**激进档**，代价是其他非白名单应用被降级，解除聚焦后自动恢复。
- 加载本地模型前先启动工具并聚焦 llama-server（与记忆中的使用方式一致）。
