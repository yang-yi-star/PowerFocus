# 统一内存模式 5 轮实测报告

> 机器：AMD Ryzen 9 8940HX（16C/32T）+ RTX 5060 Laptop 8GB + 32GB 内存
> 模型：Qwen3.8-27B-UD-Q4_K_M（15.33GB，65 层）
> 部署形态：llama-server `-ngl 20 -fa off -c 8192`，权重单份 GGUF 整体 mmap 驻留系统内存，GPU 承担前 20 层、CPU 承担剩余 45 层，共享同一份权重 —— 即等效 Apple 统一内存形态
> 测试脚本：`Test-UnifiedMemoryPerf.ps1`（本地模型产出 + 豆包监督修正），每轮固定 256 token，接口 127.0.0.1:8080/completion

---

## 一、核心结论（先行）

1. **统一内存形态可跑且稳定**：本机当前部署本身就是该形态（权重整体 mmap 在系统内存，GPU/CPU 分图层共享同一份权重），5 轮实测全部成功，无崩溃、无 OOM。
2. **生成速率**：5 轮 tokens/s 为 **1.70 / 2.60 / 2.80 / 3.11 / 3.85**，均值 **2.81**、中位 **2.80** t/s；校准轮（修正 CPU 测点后）**3.43 t/s**。
3. **资源占用**：生成期间 GPU 显存约 **6.1GB**（20 层 + KV 缓存），llama 进程真实占用 **12.59 核**，系统可用内存 **3.3~4.7GB**（偏紧）。
4. **诚实口径（重要）**：此前调度对比基线（不调动 1.20 / 温和 1.32 / 激进 1.31 t/s）是在**人为制造竞争负载**（24 个 node 进程占满 ~27 核、整机 94%）下测的；本次 5 轮是在**无竞争 + 服务热启动**（权重页缓存全热、KV 常驻）下测的。因此 2.6~3.85 t/s 与 1.2~1.3 t/s 的差距，主要来自"无竞争 + 热缓存"，不能全部归功于统一内存形态本身——同一台机器、同一个服务器进程，两种状态下的真实差异。要对比"调动 vs 不调动算力"请以调度对比报告为准（+9~10%）。

## 四、技术说明与后续建议

- **扩展能力已就绪**：`E:\PowerFocus\统一内存模式.ps1`（本地模型三段产出合并 + 监督修正，语法 0 错，9 函数加载通过）提供 start / stop / status / monitor 入口：GGUF 层数解析（qwen35.block_count=65）、GPU/内存探测、最优分层计算（8GB 显存钳制 MaxGpuLayersSafe=20）、KV 量化参数生成、权重分布监控、一键启停。
- **5 轮测试脚本**：`E:\PowerFocus\Test-UnifiedMemoryPerf.ps1`，结果 UTF-8 写入 `统一内存测试结果.txt`。
- **建议**：测试时系统可用内存只有 3.3~4.7GB，属于偏紧状态；若同时开其他大内存应用（浏览器多标签、IDE），第 5 轮那种掉速（1.7 t/s）会更容易出现。正式跑大任务前建议关掉非必要大内存程序，或让 PowerFocus 把 llama 进程提为 High 优先级（已在记忆条目 p1_AR56_Dornjg 中登记）。
