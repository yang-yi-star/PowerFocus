# 温度落盘实测与实现（2026-11-15）

## 一、为什么要做这件事

用户提出的原始问题：**「我电脑目前跑过的最高温度是多少？」**

查证结论：答不出来，原因是本机从来没有软件把温度写下来：

| 可能的数据来源 | 实测结果 |
|---|---|
| 系统 ACPI 热区 | 假值。`ECTZ_0` 恒为 95.05°C、`TZ01_0` 恒为 94.25°C，三轮间隔 8 秒采样原始值一字不差，同期 CPU 占用 6%→15%→21% |
| NVIDIA 驱动 | `nvidia-smi` 的 `GPU Current Max Temp` 返回 `N/A`，驱动不留历史峰值 |
| PowerFocus 自身 | `gpu_thermal()` 只喂前端即时显示，采样完即丢，不落任何文件 |
| 任何监控软件 | 全盘扫描 C/D/E 三个 Program Files，只有 NVIDIA 目录，未装 HWiNFO / Afterburner / GPU-Z / AIDA64 |

所以「历史最高」这条数据在本机是**从未存在过**，不是没找到。从本次改造起才开始积累。

## 四、PowerFocus 怎么改的（让程序自己写）

### 新增模块

`product\v1.00\app\temp_log.py`

- 数据源优先级：LibreHardwareMonitorLib（pythonnet）→ 失败时 GPU 退回 `nvidia-smi` → 再失败则如实置空，不填假值
- 落盘：`app_paths.log_dir()`（与 security.log 同一目录）下按天切分
  `C:\Users\Administrator.医院\AppData\Local\PowerFocus\v0.10\logs\temp-YYYYMMDD.jsonl`
- 格式：一行一条 JSON，含本地时间戳 `ts`、`epoch`、`source`（lhm / nvidia-smi / none）与各部位原始读数
- 采样间隔：30 秒（`POWERFOCUS_TEMP_INTERVAL` 可调，下限 5）
- 峰值：内存里维护本次运行峰值；启动时扫已有日志算出历史峰值
- 只读，不写任何硬件或电源设置

### 接入点（`server.py`）

1. 顶部 `import temp_log`
2. 新增路由 `GET /api/temp`（走现有 `x-pf-token` 鉴权），返回当前读数 + 本次运行峰值 + 历史峰值
3. `start_background()` 里启动采样线程，成功/失败都写 `security.audit`

### 打包与启动

- 重新打包：`product\v1.00\build\build.ps1`（自动跟随 `versions\current.json` → v0.13）
- 改造前原版备份：`dist\电脑算力调度中心.exe.bak-20261115-0649`（20,464,087 字节）
- 第 1 次打包（20,475,796 字节，06:49:40）**有竞态 bug，已作废**
- 第 2 次打包（20,475,707 字节，07:03:57）为当前使用版本
- 启动后 `/api/health`：`kernel_version=v0.13`、`ready=true`；主窗口标题 `电脑算力调度中心 v1.00`（PID 24160）

### 踩到的坑：CLR 导入竞态导致界面启动失败（已修）

第 1 次打包的 exe 在 06:50:00 启动即崩，`desktop.log` 记录：

```
File "webview\platforms\winforms.py", line 27, in <module>
    clr.AddReference('System.Windows.Forms')
AttributeError: module 'clr' has no attribute 'AddReference'
```

根因：`start_background()` 启动的温度采样线程与 pywebview 的 winforms 后端在**同一秒各自首次 `import clr`**。pythonnet 首次导入要加载 CLR（耗时可达秒级），模块对象已先进 `sys.modules`，后到的一方拿到的是半初始化模块，`AddReference` 尚未挂上，界面直接失败。

修法：在 `server.py` 的**单线程导入阶段**预加载 `import clr`（失败不致命，只影响温度源），消除并发首次导入。修复后重启，`desktop.log` 无新增致命异常，主窗口正常显示。

这条值得记住：**任何在后台线程里首次引入 pythonnet 的改动，都可能把 pywebview 的界面打死**，必须在导入阶段预热。

## 五、怎么用

- 看实时温度：托盘里 `Libre Hardware Monitor`（双击图标开窗），树里 CPU → Temperatures、GPU → Temperatures
- 查机器写下来的数据：`GET /api/temp`，请求头 `x-pf-token: <%LOCALAPPDATA%\PowerFocus\http.token 的内容>`
- 查历史峰值：`/api/temp` 的 `history_peak` 字段，或直接读 `temp-YYYYMMDD.jsonl`
- 磁盘占用：约 460 字节/条，30 秒一条 → 约 2,880 条/天 ≈ 1.3 MB/天

## 六、风险与未验证项（如实列出）

1. **CPU 空闲 91–94°C 本身不正常**。Tjmax 100°C，余量只有 6–9°C。空闲状态就贴着温度墙，说明散热（硅脂/风道/风扇曲线）有问题，建议清灰换脂或检查风扇策略。这条推翻了我此前「CPU 别超过 90°C」的建议 —— 本机空闲时就已经越线。
2. **内存 60.0 / 63.8–64.0°C 高于厂商标注的 Thermal Sensor High Limit 55°C**（Critical 85°C 才是关机线）。长时间高温对 DDR5 的稳定性有影响。
3. **固态 84.0°C 存疑**：读数在所有样本里恒定 84.0，可能是该盘传感器只报固定值或标定异常，未做交叉验证，**不能当结论用**。
4. **LHM 不运行时 PowerFocus 是否仍能读**：逻辑上 `temp_log` 自己 `Open()` 会加载驱动，但本次全程 LHM 在运行、驱动已被加载，**这个分支没有单独验证**。
5. **保留策略未定**：目前日志不自动清理，按天累积。要环形截断（比如保留 30 天）需要另外定。
6. **NVMe/HDD 的 0.0 与 84.0 已原样入日志**，没有做清洗，后续分析时需要排除。

## 八、显示端：LHM 界面为什么不显示温度，改成自建小窗

**实测事实（2026-11-15 07:15–07:25）**：LibreHardwareMonitor 的图形界面在本机只显示 CPU 的 Voltages / Powers / Clocks，**没有 Temperatures 分区**。重启界面实例（PID 5132 → 64856）、把传感器列表滚到顶、打开 View 菜单，都没有温度行。而同一目录下的 `LibreHardwareMonitorLib.dll` 用 pythonnet 加载，能稳定读到 5 项 CPU 温度、2 项 GPU、2 根内存、固态温度。

结论：**界面这条显示路径在本机不可用，库这条可用**。界面为什么缺温度分区，本轮没有查出根因，不做猜测，也不假装它正常。

**因此新建** `E:\PowerFocus\tools\temp-hud.py` —— 常驻置顶小窗，每秒刷新，固定 8 行（不随硬件数量变动）：

| 行 | 读取键 | 阈值 | 阈值来源 |
|---|---|---|---|
| CPU Tctl | Core (Tctl/Tdie) | 100°C | AMD 官方 Tjmax |
| CPU CCD 最高 | CCDs Max (Tdie) | 100°C | 同上 |
| CPU CCD 平均 | CCDs Average (Tdie) | 100°C | 同上 |
| GPU 核心 | GPU Core | 87°C | nvidia-smi Target Temperature Specification |
| GPU 显存结温 | GPU Memory Junction | 87°C | 同上 |
| 内存 #0 / #1 | DIMM #0/#1 | 85°C | SPD Thermal Sensor Critical High |
| 硬盘最高 | 各盘 Temperature 取最大 | 85°C | YMTC PC41Q 80–85 起降速 |

颜色规则：距阈值 ≤5°C 红、≤20°C 黄、其余绿；每行右侧显示「阈值·本次峰值」。读不到的行显示「—」，**不填假值**。

**为什么不用 tkinter**：本机 `D:\Python313` 缺 Tcl 数据文件，实测报 `_tkinter.TclError: Can't find a usable init.tcl`，失败。改用 pythonnet 已加载的 .NET WinForms 画界面，不引入新依赖。

**运行方式**
- 启动：`E:\PowerFocus\.venv\Scripts\pythonw.exe E:\PowerFocus\tools\temp-hud.py`（pythonw 无黑框）
- 自启：`HKCU:\Software\Microsoft\Windows\CurrentVersion\Run` → `PowerFocusTempHud`
- 退出：点 × 或按 Esc
- 回滚：删 `PowerFocusTempHud` 键、停对应 pythonw 进程、删 `tools\temp-hud.py`

只读，不改任何硬件、电源、风扇设置。
