## 三、PowerShell 侧标准做法（已查证）

来源：`$PSScriptRoot` + JSON 配置是 PowerShell 社区公认模式。

```powershell
# 1. 路径永远基于脚本自身
$configPath = Join-Path $PSScriptRoot 'config.json'

# 2. 读取时显式指定编码（5.1 下必须，否则 BOM 会导致解析失败）
$cfg = Get-Content -LiteralPath $configPath -Raw -Encoding UTF8 | ConvertFrom-Json

# 3. 用前校验必需键，别让 $null 流进下游
if (-not $cfg.CudaReservedMB) { throw "config.json 缺 CudaReservedMB" }
```

PSScriptAnalyzer 有对应规则 `AvoidUsingComputerNameHardcoded`，同等思路适用于端口与路径。

## 四、Python 侧标准做法（已查证）

**12-Factor Factor III：Config 严格代码/配置分离。**

`os.environ.get(key, default)` 被明确点名为"生产性配置债"，四条原因：

1. 类型固定为 `str`，每次读都要手转 `int`，忘一次就是 bug
2. 无存在性保证，忘设 env 要到实际用到才炸
3. **默认值到处散落，DRY 违规**
4. 敏感值 `print(config)` 就泄漏

**标准解法：`pydantic-settings` 类型化单一模型。**

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    cuda_reserved_mb: int = 512
    compute_reserve_mb: int = 1024
    llama_port: int = 8080
    app_port: int = 18080

    model_config = {"env_file": ".env", "extra": "forbid"}

settings = Settings()   # 启动即校验，缺项/类型错立即抛 ValidationError
```

**本机现状**：`pydantic 2.14.2` 已装，**`pydantic-settings` 未装**。

**但对桌面应用有个现实约束**：用户不会去设环境变量。所以配置应落在
`%LOCALAPPDATA%\PowerFocus\config.json`（已有 `app_paths.py` 处理这个目录），
env 只作为高级覆盖手段——**这比纯 12-Factor 更适合桌面场景**。

## 五、桌面应用的定制做法（结合本项目）

```
优先级（高 → 低）：
  命令行参数          ← 临时调试
  环境变量            ← 高级用户 / CI
  %LOCALAPPDATA%\PowerFocus\config.json   ← 用户配置（真正的主力）
  程序目录 config.default.json            ← 出厂默认
  代码内默认值        ← 最后兜底
```

`app_paths.py` 已经有 `DATA_SLOT`、`data_root()`、`ENV_OVERRIDE` 这套骨架，
**只需要把 `DATA_SLOT` 写死改成推导**，其余结构是对的。

## 六、最大的一处"硬编码"不是路径，是状态

`server.py` 的 `resolve_kernel()` 逻辑是：

```
扫 versions/ 下所有目录 → 读 MANIFEST.json 的 stage
→ 只接受 stage == "stable" → 取版本号最大的
→ 兜底 v0.07
```

实测各版 stage：

| 版本 | stage | 产品层会不会选中 |
|---|---|---|
| v0.09 | **stable** | **会（当前就是它）** |
| v0.10 | dev | 不会 |
| v0.11 | dev | 不会 |

**所以"以 v0.11 为目标全面对接"的第一道障碍是**：v0.11 的 `stage` 是 `dev`，
产品层压根不会加载它。这是**配置状态问题，不是代码问题**——
把 v0.11 的 `MANIFEST.json` 改成 `stage: "stable"`，产品层立刻会切过去。

但按 `VERSIONING.md` 的规矩，"stage=stable 后代码变更必须开新目录"，
所以这一改要连版本号一起走（v0.11 定稿 → 开 v0.12）。

## 七、结论

1. **438 处里只有 9 处真要动**。其余是正确写法，改了反而错。
2. **最贵的不是路径硬编码，是 `stage` 状态**——v0.11 是 dev，产品层根本不看它。
3. **`CudaReservedMB`/`ComputeReserveMB` 按比例推导**是下一步最该做的：现在是给 8GB 卡量身定制的数，你要"给服务器、给更大的电脑、更小的电脑用"，这两个数必须变成比例。
4. 网上标准解法已查证：PowerShell 用 `$PSScriptRoot` + JSON；Python 用 `pydantic-settings` 类型化模型；桌面应用配置落 `%LOCALAPPDATA%`。
