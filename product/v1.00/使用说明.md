# 电脑算力调度中心 v1.00 使用说明

> 2026-11-12 按实测修订：界面导览、对话通道、图标与入口说明已对齐 v1.00 真实形态。
> 原版备份于 `E:\PowerFocus\archive\desktop-fix-20261112-1055\docs\使用说明.md`。

## 一、这是什么

一个**通用型**桌面算力调度中心：面向**任意进程 / 任意应用**，不绑定任何单一软件。
你可以把它理解成"带对话的任务管理器 + 调度台"：选中任何应用，就能给它让路、提优先级、回收内存、冻结恢复；
也可以直接对输入框说人话，它会翻译成调度指令。

AI 模型只是它的**内置场景之一**，不是它的定义。

## 二、环境要求

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 |
| 渲染内核 | Microsoft Edge WebView2 Runtime（Win11 自带；Win10 如缺失需安装） |
| 调度内核 | PowerShell 7（pwsh） |
| 权限 | 普通用户可用；对部分系统进程操作需管理员运行 |

## 三、安装与启动

1. 进入程序目录 `E:\PowerFocus\product\v1.00`
2. 首次使用执行一次安装（创建桌面与开始菜单快捷方式）：

```powershell
.\install.ps1
```

需要开机自动启动时：

```powershell
.\install.ps1 -AutoStart
```

3. 之后双击桌面「电脑算力调度中心」即可。

   桌面**只保留一个**入口 `电脑算力调度中心.lnk`。2026-11-12 修复了历史遗留的两个重复图标，以及其中一个残留的旧 PowerShell 启动参数；现在双击等于「无参启动 exe」。图标使用 11-03 制作的项目 ico，安装脚本把 `IconLocation` 指向 `app.ico`。

也可以直接运行 `dist\电脑算力调度中心.exe`，无需安装。

卸载（只删快捷方式，不删程序文件）：

```powershell
.\install.ps1 -Uninstall
```

## 四、界面导览

v1.00 是**七页导航控制台**（WebView2 单页应用），不是老版「左进程列表 + 右对话面板」的双栏托盘界面。

```
┌ 顶栏：CPU / 内存 仪表 + 内核 / 云端 / 模型路由 状态灯 ──────────┐
├ 左侧导航：运行 → 总览 · 进程 · 场景 · 模型与对话                ┤
│           系统 → 安全态势 · 设置 · 日志                        │
│           页脚：仅监听回环地址 / 接口需令牌访问                  │
├ 右侧主区（按导航切换）                                        │
│   总览       CPU/内存/进程数/前台应用 KPI + 资源 TOP8 + 指令快捷栏│
│   进程       进程列表、选中后的调度操作条                       │
│   场景       场景预设与一键切换                                │
│   模型与对话 指令模式 / 对话模式、云端与本地通道配置             │
│   安全态势   令牌、白名单、审计                                │
│   设置       服务端口、模型凭据、路由等                         │
│   日志       运行日志查看                                      │
└──────────────────────────────────────────────────────────┘
```

- **总览**页每秒刷新；「资源占用 TOP 8」可点击跳转到进程页详情。
- **调度操作**只对"已选中"的进程生效；未选中时先点一行。
- **聚焦**分三档：普通（gentle）、强制（aggressive）、极限（godmode）。聚焦后该进程获得更高 CPU 优先级，其余进程相对让路。
- **授权调度**：内核有白名单机制，首次调度某应用前把它加入授权清单。
- **终止**是破坏性操作，会二次确认。

> 若打开后仍是老版双栏布局，说明看到的不是 `product\v1.00\dist\` 里的 exe。先查 `%LOCALAPPDATA%\PowerFocus\logs\desktop.log` 有没有本次启动记录，窗口标题应为「电脑算力调度中心 v1.00」。

## 五、对话指令示例

指令模式下，输入后会出现"将执行"预览卡片，点「执行」才会真正下发。

| 你说的话 | 实际动作 |
|---|---|
| 现在什么情况 | 查询整机与调度状态 |
| 给 chrome 加速 | 聚焦 chrome（普通档） |
| 给 chrome 全力加速 | 聚焦 chrome（极限档） |
| 解除聚焦 / 取消聚焦 | 所有进程恢复正常调度 |
| 把 notepad 优先级调到最低 | 设 notepad 优先级为 Idle |
| 把 notepad 优先级调到最高 | 设 notepad 优先级为 High |
| 清理内存 / 释放内存 | 回收空闲进程工作集 |
| 冻结 explorer | 挂起进程 |
| 恢复运行 explorer | 恢复进程 |
| 切换到游戏场景 | 应用 gaming 场景 |
| 结束 notepad | 强制终止（破坏性，需确认） |
| 限制 chrome 到 5 mbps | 网络 QoS 限速 |

切到「对话模式」后，**默认走云端 API**（凭据由 `security.py` 的 DPAPI 加密库或用户级环境变量提供）；云端未配置时才回落到本地推理服务（`127.0.0.1:8080`）。`server.py` 的 `/api/model/status` 会返回 `default_target`，可在「设置」页切换通道。

## 六、安全边界（明确不做）

- 只监听 `127.0.0.1`，不开放局域网、无远程控制。
- 不操作 PPL 保护的系统进程（lsass、csrss、services、wininit 等），界面已标记禁止。
- 不做超频、驱动、内核级改动。
- 破坏性操作（终止/施压）必须二次确认，且需本机 token。
- 写操作全部走内核白名单动作，后端不允许任意命令透传。

## 七、目录与版本

```
E:\PowerFocus\
├── 电脑算力调度中心.ico   11-03 制作的原始项目图标（古早版，保留不动）
├── versions\          内核版本目录（v0.05 / v0.06 / v0.07 ...），current.json 指向当前内核
├── product\v1.00\     产品（桌面端）目录
│   ├── app\           源码（main.py / server.py / security.py / web 七页前端）
│   ├── app.ico        项目图标副本（ASCII 路径，供 .lnk 与 PyInstaller 引用）
│   ├── dist\          打包产物（电脑算力调度中心.exe）
│   ├── build\         打包脚本 build.ps1 与 spec（已内置 --icon）
│   └── install.ps1    安装脚本
└── archive\           已退役的历史版本（v2-archive / v3-legacy-*）
```

产品版本与内核版本是两条线：产品 v1.00 依赖内核 ≥ v0.07，内核升级不影响产品安装。
根目录 `电脑算力调度中心.ps1` 只是兼容转发壳，跟随 `versions\current.json`，不再指向已归档的 `v3\`。

## 八、故障排查

| 现象 | 处理 |
|---|---|
| 双击后无窗口 | 查看 `%LOCALAPPDATA%\PowerFocus\logs\desktop.log` |
| 顶栏显示「内核 离线」 | 程序会自动拉起内核；若失败，确认 `versions\current.json` 指向的目录存在，且 `pwsh` 可用 |
| 提示「命令总线超时」 | 内核未运行或被占用；检查对应 `versions\` 目录下的心跳文件是否在刷新 |
| 操作提示「不在授权清单」 | 先点「授权调度」按钮 |
| 端口被占用 | 程序会自动从 18080 向后寻找空闲端口，无需手动处理 |
| 界面空白 | 确认已安装 WebView2 Runtime |
| 图标仍是默认图标 | 桌面右键刷新，或重跑 `.\install.ps1` 让 `IconLocation` 重新写入 |

## 九、重新打包

源码改动后：

```powershell
.\build\build.ps1 -Clean
```

产物输出到 `dist\电脑算力调度中心.exe`。打包脚本与 spec 已内置 `--icon app.ico`，exe 自带项目图标；桌面与开始菜单快捷方式的 `IconLocation` 也指向同一图标。

> 若打包时桌面端正在运行，`dist\` 里的 exe 被占用会覆盖失败。先关闭窗口再执行本脚本。
