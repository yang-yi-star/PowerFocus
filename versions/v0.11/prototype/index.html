合规与边界
卡巴斯基引擎不能随第三方安装包自由再分发授权
官方确有 OEM 嵌入产品（Kaspersky Scan Engine / Anti-Virus SDK v8），但需签订技术合作伙伴与商业授权后取得 SDK 与病毒库分发权。原型把卡巴斯基实现为「检测到已安装 → 调用 avp.com」的外部适配器，并保留 OEM 接入位，不伪造内嵌。
随包自带的真实解法可落地
ClamAV（GPLv2）官方提供 Windows portable ZIP 与 clamscan 命令行，可随安装包分发、无需系统安装；需遵守 GPLv2 并单独维护病毒库更新。这是「安装包自带杀毒能力」在工程与许可上都能成立的路径。
应用内下载入口（已跑通）实测
用户点「下载」后，应用从卡巴斯基官方分发点取 KVRT.exe 到自己的 engines\KVRT\ 目录，纯 Python 验签（WinVerifyTrust + 厂商标识 + SHA256）通过后登记为可用引擎；不写系统目录、不注册服务、不随安装包分发。EULA 5.4 禁止随第三方产品再分发，因此只做「用户主动下载 + 应用调用」。
调用已装安全软件（多引擎适配层已落地）实测
engine_adapters.py 统一 8 个引擎的「识别 → 可调用性探测 → 按官方文档构造命令 → 真实执行 → 统一报告」。对有官方 CLI 的（Defender、KES、ESET、内置 KVRT）真实调用；对无公开接口的（管家类、360、火绒 Windows 版）只识别、只引导。本机实测结论：KVRT 可用；Defender 服务被接管，真跑返回 0x800106ba；腾讯管家是卸载残留；KES / ESET 未安装且未实测，默认拒绝执行。绝不伪造命令或谎报扫描结果。
